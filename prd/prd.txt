# PRD — Interactive Globe Bidding Platform

**Working title:** GlobeBid
**Product type:** Viral interactive advertising marketplace
**Platform:** Web
**Experience:** Single-page application
**Frontend:** Next.js + React + Three.js / React Three Fiber
**Backend:** Supabase
**Payments:** Dodo Payments
**Primary device:** Desktop, fully responsive on mobile
**Design direction:** Apple.com × interactive 3D globe × Outbid-style bidding

---

# 1. Product Vision

Create the most visually impressive way on the internet for a startup, creator, brand, or individual to advertise themselves.

The entire website is one interactive 3D Earth.

Every country can be claimed.

A visitor can:

**Spin the globe → choose a country → see who controls it → outbid them → pay → instantly place their logo on that country.**

No dashboards.

No complicated signup.

No feeds.

No multiple pages.

No unnecessary navigation.

The globe itself is the product.

---

# 2. Core Product Idea

Every country on Earth is an advertising position.

Each country has its own leaderboard.

The startup/person with the **highest total stake** on that country controls it.

Their:

* logo
* brand name
* URL
* country ownership
* amount staked

become visible publicly.

Someone else can outbid them at any time.

The current owner can later reclaim the country by topping up their previous contribution.

### Example

USA:

Current owner:

**Acme AI**

Total stake:

**$100**

Minimum required to take #1:

**$105**

Another company pays $105.

Now:

**NewCo owns USA — $105**

Acme still retains its historical $100 stake.

If Acme wants USA again:

Acme only needs to add:

**$10**

Their total becomes:

**$110**

Acme owns USA again.

This creates a continuous competitive loop instead of every bid being a completely new purchase.

# 19. Recommended Bidding Rules

## Starting price

Every unclaimed country:

**$5**

This matches the low-friction viral behaviour seen in similar products.

---

## Minimum increment

For MVP:

```text
Current price < $50      → +$5
$50–$199                 → +$10
$200–$999                → +$25
$1,000+                  → +$50
```

This is preferable to forcing every takeover to be 1.5×.

A 1.5× system becomes expensive extremely quickly.

This model still creates competition while keeping countries liquid.

---

# 20. Cumulative Stake

Each advertiser retains their historical contribution to a specific country.

Example:

```text
Company A → $50
Company B → $60
Company A → adds $15
```

Totals:

```text
Company A → $65
Company B → $60
```

Company A becomes #1.

This creates:

* retention
* repeat purchases
* rivalry
* lower friction for previous owners
* more long-term revenue

---

# 21. Payment Philosophy

Payments are **non-refundable advertising purchases** except:

* duplicate payment
* technical payment error
* legal requirement
* merchant-approved refund

Getting outbid does NOT create a refund.

The user already purchased advertising exposure during the period where they held the placement.

Clear microcopy before checkout:

> Your payment purchases advertising placement. Another advertiser may later outbid your total stake. Previous contributions remain attached to your brand and can be topped up to reclaim the country.

# 22. Dodo Payments Integration

Use:

**Dodo Payments one-time payment**

Preferred checkout UX:

### Dodo Overlay Checkout

This preserves the single-page experience.

The visitor should ideally never feel like they left the globe.

If Overlay Checkout creates implementation limitations, use Dodo Checkout Sessions.

Dodo currently supports Checkout Sessions, overlay checkout and inline checkout for one-time purchases. Checkout Sessions are created server-side, and successful payment should be trusted only after receiving the signed payment webhook.

# 23. Payment Flow

```text
Country selected
       ↓
Brand information
       ↓
Bid amount
       ↓
Create pending bid
       ↓
Server calculates minimum price again
       ↓
Create Dodo checkout session
       ↓
Payment
       ↓
Dodo webhook
payment.succeeded
       ↓
Server validates payment
       ↓
Atomic bid transaction
       ↓
Determine country leader
       ↓
Update ownership
       ↓
Supabase Realtime event
       ↓
Everyone watching sees ownership change
```

CRITICAL:

The browser returning from Dodo must **never** determine successful ownership.

Only:

`payment.succeeded`

webhook can activate the bid.

---

# 24. Payment Race Condition

Important scenario:

Current USA price:

`$100`

Person A starts checkout for:

`$105`

Person B starts:

`$110`

B pays first.

USA becomes:

`$110`

A then pays $105.

A's payment remains a legitimate stake.

Their total becomes $105.

But they are NOT #1.

Success screen:

```text
Your $105 stake is live.

Someone moved faster and currently holds USA at $110.

Add $10 to take the lead.

[ Take USA for $115 ]
```

Never silently overwrite B.

# 26. Idempotency

Dodo webhook handlers must be idempotent.

Store:

`webhook_id`

If webhook has already been processed:

return:

`200 OK`

without repeating bid allocation.

Dodo webhooks use signed payloads and may deliver payment state changes asynchronously, so event processing must be idempotent.

# 44. Atomic Leader Calculation

Payment activation must run inside a database transaction.

Conceptually:

```text
BEGIN

lock advertiser/country stake

add payment amount

calculate new total

get highest total stake for country

if leader changed:
    update current owner
    create ownership history
    generate activity event

mark bid paid

COMMIT
```

This prevents two simultaneous payments from corrupting country ownership.

# 57. Reference Products — What to Copy Conceptually

## Outbid

Useful pattern:

**price is immediately understandable.**

User sees exactly what purchasing the position costs.

Outbid's interface prominently exposes the current price and gives an immediate "claim" action, which is a major reason the mechanic requires almost no explanation.

---

## Warmap

Useful pattern:

**territory creates emotional ownership.**

Its core proposition is simply that a company controls a country until somebody takes it.

Do not copy its war-themed visual design.

Make ours significantly more premium.

---

## WorldMap

Useful pattern:

**3D Earth makes the concept instantly understandable.**

It also uses accumulated stake, allowing users who lose position to top up instead of discarding their historical contribution.

This should remain.

---

## BrandMyPC / BrandMyFridge

Useful pattern:

The physical visual itself is the inventory.

People immediately understand what they are purchasing.

BrandMyPC presents visual placements directly on the object and makes each slot actionable instead of separating the object from the purchase UI.

Our equivalent:

**Earth itself is the inventory.**

# 64. Security

Never expose:

```text
DODO_PAYMENTS_API_KEY
DODO_WEBHOOK_SECRET
SUPABASE_SECRET_KEY
SUPABASE_SERVICE_ROLE
```

Browser receives only the Supabase publishable key with tightly configured RLS.

Sensitive bidding logic remains server-side.

Supabase explicitly warns that secret/service-role credentials bypass RLS and must never be exposed in frontend code.

---

# 65. Critical Backend Rule

Never trust:

```text
country price
current owner
bid minimum
payment amount
brand ownership
```

from frontend input.

The server recalculates everything before creating checkout.

# 66. Realtime Behaviour

Subscribe to:

```text
country_updates
global_activity
stats
```

If someone buys Japan while 400 people are on the website:

every connected globe should update Japan automatically.

Old logo disappears.

New logo appears.

Activity toast:

```text
Sony just took Japan · $420
```

No refresh.

Supabase supports subscriptions to Postgres changes for this type of realtime synchronization.

# 69. MVP Acceptance Criteria

The MVP is ready to launch when:

* Globe renders smoothly on desktop/mobile.
* Every supported country can be selected.
* Country selection rotates Earth correctly.
* Unclaimed countries can be purchased.
* Existing countries can be outbid.
* Brand metadata can be entered.
* Logos upload correctly.
* Checkout session is server-generated.
* Dodo webhook signatures are verified.
* `payment.succeeded` creates a stake exactly once.
* Simultaneous bids cannot corrupt ownership.
* Ownership changes appear realtime.
* Brand logo changes immediately.
* Outbound clicks are recorded.
* Social share image is generated.
* Outbid owner receives email.
* URLs and brands can be administratively blocked.
* Terms clearly explain advertising-placement rules.
* Mobile bottom sheet works correctly.
* Payment/test webhook flows pass before switching Dodo into live mode.
